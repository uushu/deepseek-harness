# Agent Note: Other World Thread built-in theme

Status: proposed

## Problem

Web 客户端目前只持久化浅色、深色与跟随系统三种外观偏好，而通过注册机制加入的扩展主题只存在于当前进程。因此，一个正式产品主题既无法在回环地址客户端重启后保留，也无法进入防止首屏配色闪烁的插件前引导流程。新的 DSH 视觉方向还需要一种受控方式引入深蓝画布、青色系统焦点、暖橙操作色、布料感中性色以及纽扣／缝线意象，同时不能把颜色字面量或主题选择器散落到各个功能包。

## Proposal

把 `other-world` 加入可持久化的内置偏好，并作为基于深色配色的 `ThemeDefinition`。颜色字面值统一放在 `ui-theme/src/styles/other-world.css`，`other-world-theme.ts` 只负责把这些静态值映射到已有 `--dsw-alias-*` 与 `--dsw-specific-*` 语义角色，再由现有 ThemePresenter 应用主题快照。Host 引导脚本在外壳挂载前应用同一组别名映射，确保首帧直接匹配持久化偏好。外观设置增加第四个选项，并使用原创的四孔纽扣图形。功能包继续只消费语义 token，不感知具体主题。

视觉来源采用定格动画哥特童话的设计语法，而不是复制电影美术资产：深冷环境空间、有限的暖色行动光、线与纽扣的触觉暗示、框中框纵深，以及克制的手工不规则感。产品主题不包含角色肖像、电影 Logo、电影截图壁纸或其他直接影视资产。

## Alternatives considered

**把 Other World 保持为第三方注册主题。** 这样可以维持现有注册边界，但会失去持久化选择与 Host 首屏引导，用户每次载入时仍可能先看到基础主题，并且主题只在当前进程有效。

**按主题分支各组件 CSS。** 在 conversation、sidebar、composer 和 primitives 中分别加入主题选择器或颜色字面量会让同一套配色在多个所有方中重复，并违反现有 Web 样式约定。

**使用电影截图或角色图作为背景。** 直接图片会削弱文字对比度，把产品界面绑定到受版权保护的视觉资产，也会让主题退化成换肤而不是可复用的设计语言。

## Acceptance criteria

- `other-world` 能被 Host settings schema 接受，出现在外观设置中，通过现有偏好路径持久化，并解析为深色基底主题。
- 插件前引导会应用并在离开主题时清理与 ThemePresenter 后续接管相同的语义别名覆盖，首屏不出现基础主题闪烁。
- 配色字面值只位于主题所有方的样式表；功能组件继续消费语义别名，不增加主题选择器。
- Theme runtime、Host bootstrap 与 Appearance 测试覆盖新偏好，并在合并前刷新 Web 可视化快照。
- 中英文主题文档描述同一份当前约定，并刷新翻译配对记录。

## Risks

当前别名映射足以重着色已有外壳，但不会自动生成视觉研究中的全部触觉意象；缝线边界、隧道转场等叙事化处理仍需要后续组件工作，并继续通过语义 token 实现。引导流程会把别名映射序列化到 index 响应中，因此内联脚本体积会有所增加。可访问性、代码可读性与长时间使用舒适度始终优先于对参考电影高反差画面的完全复刻。
